# 接入手册：sprite-designer

本手册供 AI 按当前客户端和项目实际情况完成接入。入口是 [README 中的聊天指导](../README.md)，资源以 README 清单为准。这里没有安装器、npm 入口或初始化脚本。

## 读取与选择资源

先识别用户选定页面或 checkout 的版本；网页来源应把该分支或标签解析为一个完整 Git 提交，随后从同一提交读取 README 清单、[角色主源](../templates/agent.md)及用户选定实践的完整目录，避免分支更新混入不同版本。资源相对链接跟随所选版本；历史 **v0.2.0** 可显式选择，以该标签实际包含的文件为准。最后报告来源和完整提交，不建立额外安装登记。无法核实提交时明确未固定版本；用户明确采用本地未提交修改时保留其内容，并如实标为工作区修改，不能声称已被提交固定。

默认只接入角色。本角色没有附带实践，不为它创建空的 Skill 目录。单独使用角色不要求 Node.js、其他角色、固定流程或技术档案。

阅读当前请求、项目已有规则和真实目录。尊重已明确的模块范围、技术与文档约定，不把资源里的可选方法升级为项目强制规则。

接入时主动引导用户确认本次角色、上游资料 host repo、产物保存 repo/目录。先读当前请求与已有约定，已明确的不重问；把缺项合并为一次自然语言询问，允许“暂无/稍后配置”。先完成角色接入，不因未答业务信息而阻塞；真正读取时再补所需版本、功能或文件路径。不创建配置文件或问卷，也不在后续任务重复询问已知上下文。

## 识别当前客户端

先使用当前会话提供的客户端信息和项目已有的角色、指令或 Skill 目录判断。已有多个工具目录并不代表应当全部写入；只处理当前实际使用的客户端。不要先给用户一张工具选择或环境配置问卷。

下面是已有三种机制的路径参考，只有确认当前客户端支持时才采用；格式要求见本手册下文。

| 客户端机制 | 角色位置 | 已选 Skill 位置 |
| --- | --- | --- |
| Codex 项目角色 | `.codex/agents/sprite-designer.toml` | `.agents/skills/<名称>/` |
| Claude Code 项目角色 | `.claude/agents/sprite-designer.md` | `.claude/skills/<名称>/` |
| GitHub Copilot 项目角色 | `.github/agents/sprite-designer.agent.md` | `.github/skills/<名称>/` |

其他客户端优先沿用其已经使用的项目指令或资源机制，必要时查阅该客户端的官方说明。无法确认原生机制时，可以保留普通 Markdown，由 AI 显式读取；不用猜路径，也不因客户端名字未知而停下所有工作。

没有既有位置约定时，普通文件可放在 `.sprite/roles/sprite-designer.md` 和 `.sprite/skills/<名称>/`。这是资源存放示例，不是所有客户端都会自动扫描的约定。如果项目已忽略该目录、已有更合适的文档目录，沿用项目现有位置并说明实际路径。

## 放置角色文件

完整保留角色正文，按所选机制做最薄的一层格式调整：

| 目标格式 | 必需内容 |
| --- | --- |
| 普通 Markdown | 原样保存 `templates/agent.md`，由当前 AI 读取 |
| Codex TOML | `name` 为 `sprite-designer`，`description` 来自主源的角色介绍，`developer_instructions` 为完整正文；使用合法 TOML 字符串并正确处理换行与引号 |
| Claude / Copilot Markdown | YAML frontmatter 中提供 `name: sprite-designer` 和来自主源的 `description`；frontmatter 后放完整角色正文 |

不擅自加入模型、权限、工具白名单或新工作流配置。目标文件已存在时先比较，不为了统一格式覆盖用户修改。资源路径必须位于实际目标项目，遇到链接或同名目录时先核实，避免写到其他项目。

客户端明确需要入口引用时，沿用其实际格式，仅补充所需引用，保留原有内容。不要用角色正文替换项目现有的总规则或改全局配置。无需入口引用的机制不额外添加配置。

## 已有内容与后续维护

先识别已有角色或 Skill 的位置，优先复用，不因目录不同就另建副本绕过用户的修改。

- 内容相同：直接复用，不重复写入。
- 用户已修改：保留自定义，比较来源与影响；能够明确保留现有意图的局部合并可以完成，存在实质冲突时只提出相关问题，其他独立资源继续处理。
- 追加资源：只添加指定角色或实践；未选中不表示删除。
- 更新资源：读取明确的新版本，与当前文件比较；同一 Skill 保持完整版本，保留用户新增文件。
- 移除资源：只处理用户明确指定的范围；先核对是否含自定义或仍有引用，不删除整个共享目录或其他角色。

旧版本留下的文件不是重新安装的理由。不要清空现有内容，也不要生成、修补或伪造安装记录；当前流程依据真实文件与用户请求维护。

## 接入后的检查

重新读取实际写入的文件，核对角色正文和元数据，确认已选 Skill 的本地相对引用全部存在。检查改动清单，确保其他角色、应用代码、用户规则与未选资源未被改变。

客户端提供实际发现或角色调用检查时，按其机制验证；否则只报告已保存的文件。不要把文件存在说成已自动加载，也不要把主代理读取说明说成启动了原生子代理。

接入完成时直接列出本次尚需用户做的步骤：是否要按客户端提示信任项目、登录、重新加载/重启会话，以及如何选择或调用角色。只列实际需要的步骤，不要求改全局配置或重复授权；未发现角色时先核对安装后的完整正文，再显式读取使用。客户端行为以当前官方说明为准，不用历史测试结果替代现场检查。

回复用户时简明列出：来源版本、实际文件位置、选中资源、完成的检查以及下一步使用方式。新会话没有自动加载时，可明确要求 AI 先读取相应本地文件。

## 业务产物与资源分开

纯角色接入只放置角色和所选实践。当前任务确需跨 Git 读取、固定版本、比较或导出留存时，复用已有 bridge；缺失或能力不足则按 [bridge README 与手册](https://github.com/ai-sprites/artifact-bridge)把同一明确版本的完整 Skill 补齐到当前客户端已有目录，保留自定义并告知用户，无需再单独确认安装；不新增安装器、登记或问卷。用户拒绝安装或权限、网络不足时说明限制，继续独立部分；本地文件不触发安装。产物按用户指定业务仓库/目录或项目约定落盘，资料 host repo 与版本亦沿用明确选择；路径与 Git 条件见 [产物交接说明](artifact-handoff.md)。

## 权限不足时

有文件写入能力就可以完成 Markdown 与 Skill 文件放置，不要求执行初始化命令。只有聊天读取权限时，先在本会话使用已读到的角色或参考，明确没有写入项目，也不承诺跨会话记忆。

无法读取链接时，说明具体缺少的源文件，请用户提供正文或附件。不要根据名称猜出一份角色再声称来自本仓库。
