# 接入手册：sprite-designer

用户直接粘贴 [README 的白话 prompt](../README.md)，由 AI 完成接入。

## 接入当前项目

根据当前会话和项目情况判断客户端，沿用它支持的接入方式；不确定且影响接入时再查证或询问用户。

从同一明确版本读取 README 资源清单、[角色定义](../templates/agent.md)和本职 [sprite-designer-workflow](../skills/sprite-designer-workflow/SKILL.md) 的完整目录，默认一起接入。其他专项 Skill 按需选择，也可单独使用 Skill；用户明确只要职责定义时说明尚未带入执行能力。网页来源先固定到完整提交，本地未提交内容如实标注；取不到源文件就说明缺项，不自行编写替代品。

原样复制角色正文、Skill、工作流、模板和随附文件，保持资源名称与内部相对目录，只适配目标客户端必要的文件位置、格式和入口引用。专业内容不删改，项目已有规则和自定义继续保留。角色负责职责与清单，实际执行读取对应 Skill；接入本身不填写业务模板，也不建立安装登记。

## 资料和产物放哪里

资料来源仓库（host repo）与产物保存仓库可以不同。沿用已明确的仓库，缺项合并用白话问一次，允许稍后确定并先完成接入；实际使用时再补必需版本和文件。读取资料使用其真实位置，本角色新增或更新的业务产物统一放在业务仓库根目录下的 `docs/designer/`，可在其中按功能分子目录，不再选择散落位置。

本次涉及的旧产物若散落在其他位置，迁入对应角色目录并同步文档链接、已有索引和消费引用；保留内容、自定义和手写修改，目标有同名文件时先比对合并，不能覆盖或丢弃用户内容。其他角色产物归各自 `docs/<角色名>/`。角色/Skill 安装资源和正常代码、测试文件仍使用各自位置，接入本身不生成业务产物。

本地资料直接使用。确需跨 Git 读取、固定版本或导出时，按 [bridge 接入手册](https://github.com/ai-sprites/artifact-bridge/blob/main/docs/installation.md)复用或补齐完整 Skill 并告知用户，无需另发安装指令；用户已拒绝或条件不足时说明限制。角色可以独立使用，业务留存见 [产物交接说明](artifact-handoff.md)。

## 已有内容与后续维护

沿用已有资源位置；相同内容直接复用，用户自定义保留，实质冲突只询问相关部分。更新时完整采用同一版本，补齐旧版缺少的本职 Skill；不因追加或更新删除未选资源。移除只处理用户指定范围，保护自定义及仍被引用的文件。

## 完成后告诉用户

核对实际文件、正文完整性和相对引用，然后简明说明来源版本、保存位置与调用方式。按当前环境验证加载情况，区分“已保存”“已加载”和“已执行”。

需要用户亲自完成的步骤，按现场情况列成简短清单；没有就不加。只有聊天权限时可先在本会话使用，明确未写入项目及尚未完成的部分。
