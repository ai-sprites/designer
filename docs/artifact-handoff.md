# 产物留存与可选交接

角色可自由组合，资料 host repo、版本和功能或文件由用户指定，已有项目约定就沿用；资料 host repo 可以与本次产物保存仓库不同。按本角色的交付要求，AI 把设计说明、交互状态与实际素材实际保存到指定业务仓库的工作区/目录，并交付链接；只有聊天权限时明确没有落盘。

项目设计基线保留跨功能共用的规则；无既有位置时存到 `docs/design-baseline.md`，功能说明引用它。用户要求建立或更新时必须实际保存，已有基线和人工维护段按 Skill 规则保护。跨仓交接须显式选入实际使用的 baseline、功能说明和必要附件；仅在功能说明放一个基线链接不会让 bridge 自动获取它，不为每个功能复制一份基线。

## 哪些目录放什么

| 内容 | 位置和路径基准 |
| --- | --- |
| 角色与 Skill 指令 | 接入手册中实际选择的客户端资源目录 |
| 本角色业务文档 | 用户指定的业务仓库/目录优先，其次沿用项目位置；无约定时可用 `docs/artifacts/<feature-id>/design.md` |
| 项目共用设计基线 | 已有位置优先，无约定时用 `docs/design-baseline.md`；跨功能引用同一主源 |
| 代码、配置、测试及已有契约 | 留在实际所属仓库与现有位置，交接仓库、提交和文件路径 |
| 可选功能索引 | 资料 Git 仓库根的 `artifacts.json`；已有其他位置可用 `--index` |
| 消费项目的版本锁 | 在该项目目录运行 bridge，默认 `.sprite/artifacts.lock.json` |
| 按需导出的资料副本 | 支持 `export` 的 bridge 可保留到其返回的输出目录，按 `manifest.json` 找到原始文件 |

不要把角色资源仓库、已安装 Skill、用户级缓存或临时目录当成业务产物默认保存位置。现有文件无需为了示例搬迁；文件路径含空格时交接和运行命令都保留完整路径。Markdown 链接相对所在文档，索引 `path` 则始终相对资料 Git 根，二者不能混用。

## 按功能映射已有文件

只在需要按功能查找时创建或更新索引；明确提供 `--path` 也能直接读取。下面是格式示例，要替换为真实功能标识和已保存路径：

```json
{
  "features": {
    "feature-id": {
      "documents": [
        { "kind": "design", "path": "docs/artifacts/feature-id/design.md" },
        { "kind": "design", "path": "docs/design-baseline.md" }
      ]
    }
  }
}
```

例子中的 baseline 只有已保存且本次需要时才登记；多个功能可以引用同一个实际文件，或交接时以 `--path` 选择它。

功能标识保持稳定，索引只登记已有资料；`kind` 是资料类别，不是角色安装依赖。已有其他角色、人工或外部工具产物可以直接登记，不要求全部类别存在。更新现有索引时保留其他功能与自定义字段。项目已有资料索引或入口时，新建、更新、改名、移动或删除业务文档要同步对应链接和简短说明，移除失效项；只登记实际文件，不为维护入口复制外部正文。确认依据和待确定项如实记录，不把生成文档当成已经确认。

图片等附件若要通过 bridge 留存，也必须各自列在 `documents` 或 `--path` 中。正文中的链接不会自动展开，目录也不会递归读取；检查所有交接必需文件是否均已选择。HTTP(S) 外链只保留地址，不等于已归档网页、Figma 文件或链接中的附件；需要保留内容时，在已有权限内导出并单独登记本地文件。

## 真正交到另一个项目之前

1. AI 核对实际文件与链接；资料正文、索引和必要附件必须存在于选定的同一 Git 提交中。工作区改动、未跟踪文件或被忽略文件不会被 Git 读取器带走。
2. 在已有授权内完成正常 Git 协作；未提交、未推送或远端无法获取时，说明具体尚缺步骤。锁和导出结果不会替用户发布上游，也不会自动同步后续变化。
3. 当前任务确需跨 Git 读取、固定版本、比较或导出留存时，AI 复用已有 bridge；缺失或能力不足则按其 [README 与接入手册](https://github.com/ai-sprites/artifact-bridge)补齐同一明确版本的完整 Skill 到当前客户端已有目录，保留自定义并告知用户，无需再单独确认安装。运行需 Node.js 20+、Git、执行权限和源仓库认证；用户拒绝安装或权限、网络不足时，说明限制并继续独立部分，必要登录由用户完成。
4. AI 在消费项目目录运行 `pin` 或已有锁的 `read`，核对完整提交与读取结果（`pin` 返回的 `data`，或 `read` 的顶层结果）中的 `complete`、`errors` 和逐项状态，不能只看退出码。需要独立留存/交付副本时，再用支持该命令的版本执行 `export`，核对返回的 `manifest` 与落盘 `manifest.json` 并交付实际输出目录；超限、缺文件与外链等未保留内容逐项说明。
5. 多人需要同一依据时，通过正常 Git 协作分享消费项目的锁；先检查忽略规则，若默认 `.sprite/` 未纳入协作，可按项目约定用 `--lock` 选择可分享的路径并报告。各机器使用自己的认证和缓存。需要采用上游变化时先比较，再明确采用比较得到的完整提交。为新机器持续可取，应由团队保留采用提交可达的分支或标签。

普通本地文件和纯角色安装无需 bridge；无法接入时直接交付已有文件、仓库、版本与待确定项。接收方无需安装生产这些文件的角色。保留到本地、提交到 Git、远端可获取、导出副本是不同完成状态，最终说明以实际证据为准。

bridge 只读上游，不自动推送用户指定的资料仓库。参数与导出格式以当前采用版本的 [Skill 与参考文档](https://github.com/ai-sprites/artifact-bridge#资源清单) 为准，不声称已运行缺失的能力。
